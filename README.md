# LinguaDomains

Language-learning platform organized by **professional domain** (IT, Medical, Business, Legal, Tourism, ...) with AI-generated lessons. The UI, domain catalog and lesson explanations support 25 base languages; code, comments and docs are in English.

**Stack:** Node.js + Express · Supabase (Auth + Postgres, free tier) · Groq API (Llama 3.3, free) · vanilla HTML/CSS/JS.

## User flow

1. **Login / Sign up** — email + password or Google
2. **Onboarding** — pick a language → CEFR level → domains → topics of interest
3. **Dashboard** — domains, topics, progress, switch active language. Hide statistics with the card's × button and restore them through **Widgets**. The layout adapts to the visible cards; the selection is shared across the account's languages and synced through Supabase Auth user metadata, with a per-user local cache for offline edits.
4. **Lesson** — generated by AI on first visit (then cached in DB): vocabulary, dialogue, grammar, quiz, tips. Unfinished lessons resume at the last exercise, including entered answers and the current vocabulary card. The dashboard links to the latest unfinished lesson; the final quiz score is saved on completion.

## Setup (one time)

### 1. Supabase (free)

1. Create a project at <https://supabase.com> → **New project**.
2. **SQL Editor** → **New query** → paste `supabase/schema.sql` → **Run**.
   Then run every numbered SQL file in `supabase/migrations/` in ascending order (002 through 012). The repository does not apply remote migrations automatically. For an existing project, do not rerun `schema.sql`; apply only migrations that have not already been applied, in numeric order. Keep a record of applied files to avoid replaying non-idempotent policy changes.
   Migration 006 adds localized catalogs and lesson caches. Migration 007 adds cross-device lesson resume; migration 008 stores personal lesson variants; migration 009 adds test-based promotion; migration 010 makes the shared lesson cache server-managed; migration 011 moves scoring to an answer-key-backed RPC and separates selected from earned level; migration 012 makes onboarding atomic. These files must be applied in order because later migrations depend on earlier schema.
3. **Project Settings → API** → copy `Project URL` and the `anon public` key.
4. **Authentication → URL Configuration**:
   - Site URL: `http://localhost:3000`
   - Redirect URLs: add `http://localhost:3000/login`
   - For deployment, set the Site URL to the public HTTPS app URL and add its exact login URL (for example, `https://your-domain.example/login`) to Redirect URLs. The password-reset link redirects back to `/login`.
5. **Authentication → Providers → Email**: make sure Email provider is enabled. To deliver recovery emails to real users reliably, configure a custom SMTP provider under **Project Settings → Authentication → SMTP Settings**; the built-in sender is intended for limited testing and may not deliver to arbitrary addresses.
6. (Optional, for faster local development) disable *Confirm email* so sign-ups don't require email confirmation. This is separate from password recovery.

### 2. Google login

1. <https://console.cloud.google.com> → create a project → **APIs & Services → OAuth consent screen** → External → fill in app name and support email → Save.
2. **Credentials → Create Credentials → OAuth client ID** → *Web application*:
   - Authorized JavaScript origins: `http://localhost:3000`
   - Authorized redirect URIs: `https://<SUPABASE-PROJECT-ID>.supabase.co/auth/v1/callback`
     (the exact URL shown by Supabase in the next step)
3. Copy **Client ID** and **Client Secret**.
4. In Supabase: **Authentication → Providers → Google** → Enable → paste Client ID and Client Secret → Save.

### 3. Groq (free AI)

1. <https://console.groq.com> → free account → **API Keys → Create API Key**.
2. Copy the key (`gsk_...`).

### 4. Environment variables

```bash
cp .env.example .env
```

Fill in `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, and `GROQ_API_KEY`. The service-role key is used only by the server to cache lessons after its generation and validation flow; never put it in browser code or commit a real key.
Lesson generation is limited by default to 10 authenticated requests per user per minute, 3 active generations per server process, and 1 active generation per user. These in-memory limits reset when the process restarts and are not shared across multiple server replicas.
Groq `408`, `425`, and `5xx` failures retry with bounded exponential backoff (500 ms base, 8 s cap by default); other non-quota `4xx` responses fail without retry. Request timeouts and retry waits are capped by the lesson-generation deadline. `GROQ_RETRY_BASE_MS` and `GROQ_RETRY_MAX_MS` can override the backoff bounds.

## Run

```bash
npm ci
npm run dev        # http://localhost:3000
```

The app runs directly in Node.js and the browser; it does not need a generated bundle. Reading validation and lesson-duration estimates share language-aware word segmentation, so Chinese/Japanese text is not incorrectly treated as one whitespace-delimited word.
The browser Supabase SDK is pinned to an exact version in both `package.json` and its CDN import; the build check fails if they drift. Change the dependency and URL together, then refresh `package-lock.json` with npm.
The server sets baseline browser security headers, and profile avatars are rendered with DOM APIs only after HTTPS URL validation. A strict Content Security Policy is deferred: pages still use inline scripts/styles and the Supabase endpoint is configured dynamically, so CSP needs a nonce/hash and endpoint strategy first.
Run `npm run build` to check JavaScript syntax and apply `schema.sql` plus every ordered
migration to a disposable local PGlite database. `npm run check:schema` runs just the
database check. These checks validate the repository schema; they do not inspect or
change a deployed Supabase project. In VS Code, **Run Build Task** runs the same checks. Run `npm test` for
the automated tests, and `npm start` to start the server without file watching.
Run `npm run evaluate:lessons` for a deterministic offline check of representative valid/invalid lesson contracts; it reports valid-lesson acceptance, invalid-lesson rejection, and overall classification accuracy without calling an AI provider.

If startup hangs while loading dependencies (including macOS cloud-offloaded
`node_modules` files), run `npm ci` to reinstall the versions in `package-lock.json`,
then run `npm run build` and `npm test` again.

## Deployment and health checks

Run the build, schema validation, offline lesson evaluation, and tests before release:

```bash
npm ci
npm run build
npm run evaluate:lessons
npm test
npm start
```

For a production image/server, install runtime dependencies with `npm ci --omit=dev`, set the required environment variables from `.env.example`, and provide HTTPS through the hosting platform or reverse proxy. Configure Supabase Site URL and redirect URLs for the public HTTPS origin. Do not run SQL migrations as part of app startup; apply and verify them separately.

`GET /api/health/live` reports whether the Node process is responding. `GET /api/health/ready` returns 200 only when Supabase URL/keys and the Groq key are configured, otherwise 503. Readiness checks configuration only; it does not make network calls or prove that Supabase/Groq are reachable. Lesson rate limits, concurrency limits, and speech/audio caches are in-process, so use a shared limiter/cache before scaling to multiple replicas.

## Accessibility release checks

The app includes keyboard-operated controls, translated labels, RTL layout, and microphone/speech features, but no automated WCAG conformance score is claimed. Before release, manually verify:

- Complete login, onboarding, lesson, quiz, review, settings, export, and deletion flows with keyboard only; confirm visible focus and that dialogs return focus to their trigger.
- Announcements and recovery paths for validation, network, audio, microphone-permission, and save errors with a screen reader; verify focus moves to actionable errors.
- Text and control contrast in light/dark themes, zoom/reflow at narrow widths, and Arabic/Hebrew RTL layouts.
- Microphone denial, unsupported media formats, and unavailable audio providers without trapping the learner or losing entered answers.

## Database

| Table | Purpose |
|---|---|
| `profiles` | user data (auto-created on sign-up by trigger) |
| `languages` | available languages |
| `domains` | domains + each domain's topic list |
| `domain_translations` | domain names, descriptions and topic labels in each base language |
| `user_languages` | user's chosen languages + level |
| `user_domains` | chosen domains + topics, per language |
| `lessons` | AI-generated lessons (unique cache per language+domain+topic+level) |
| `lesson_localizations` | lesson content in other base languages, sharing the original lesson id |
| `user_progress` | unfinished exercise state, private regenerated lesson variant, completed lessons + quiz score |
| `lesson_attempts` | append-only test results, including retakes, per learner/language/level |

All tables use **Row Level Security**: a user can only read/write their own personal rows; languages and domains are read-only, and authenticated clients can read shared lessons but cannot write them. The server writes shared lessons and localizations with its private service-role key only after validating a freshly generated result.
The account JSON export and dashboard progress/lesson/vocabulary reads fetch deterministic pages until the exact row count is reached, rather than relying on Supabase's default response limit. The export remains limited to the account's personal tables; shared lesson content is not included.

Promotion advances one CEFR level when the arithmetic mean of the learner's **latest 10 completed tests at the current language and level is strictly above 90%**. Every result counts, including low scores and retakes; an eleventh test replaces the oldest result in the window. Topic/lesson counts are not promotion requirements. A new level needs its own ten tests; C2 is the ceiling. Stable attempt IDs survive unfinished-lesson resumes and save retries, so one submission cannot count twice. The progress update and history insert share a database transaction, and the promotion RPC checks the same window under a language-row lock.

Existing lesson scores and unfinished lessons are preserved. Since the old database overwrote earlier attempts, the consecutive-test window starts with completions recorded after migration 009; old scores are not presented as reconstructed test history.

Choose the base language in **Settings**, before or after login. It is saved in `profiles.native_language` as a language code and restored on login; a choice made before login takes precedence. Domain slugs and topic keys stay stable in the learning tables, while `domain_translations` holds their localized display text. The matching catalogs in `public/js/catalog/` also work when the database translation table is unavailable. Keep topic array order aligned with `catalog/ro.js` when updating a bundled catalog.

The resume card counts completed exercises, including individual vocabulary cards, and shows a progress bar. Regeneration sends the previous variants' target words, phrases and scenario summaries to the generator. Duplicate target material is rejected and retried before building the remaining sections from the new vocabulary plan. A separate AI review checks professional facts, topic/level fit, grammar and answer correctness, repairing rejected sections. The saved variant retains recent history (240 terms, 128 phrases) and belongs to the learner; the shared cache and other learners' progress stay intact.

Generation uses a domain-specific workplace brief and a separate teaching design for each [CEFR level](https://www.coe.int/en/web/common-european-framework-reference-languages/table-1-cefr-3.3-common-reference-levels-global-scale): concrete instructions at A1, routine exchanges at A2, process explanations at B1, technical decisions at B2, nuanced professional analysis at C1, and precise expert reformulation at C2. Grammar and sentence complexity follow the target language, while each section stays inside the chosen topic.

## Brand and audio

The shared brand component, SVG asset and favicon use the artwork from `logo_ld_varianta_3.svg`, cropped to its square tile. Its original light background and dark LD mark remain visible in either theme.

Listening uses Microsoft neural voices through the server-side [msedge-tts](https://github.com/Migushthe2nd/MsEdgeTTS) library instead of browser speech synthesis. Settings offer male and female voices with a playable sample in the interface language. The choice is saved in this browser and applies to words, phrases, complete dialogues, reading passages and review cards. Each of the 25 learning languages has both native voice types; English uses Andrew or Ava Multilingual. The settings and slow buttons change synthesis speed, preserving a natural pitch. Server and browser audio caches distinguish voices as well as speed. Web Audio and a reusable audio element are unlocked during the click; the audio element plays the same neural MP3 if Web Audio stalls or cannot decode it. Expired sessions get one refresh, and invalid audio is not cached. Changing the voice, speed or exercise, or leaving the page, cancels playback and pending requests.

Only the text being read and its language, voice and speed are sent to Microsoft's online Read Aloud service; account details and microphone recordings are not sent by this endpoint. No additional API key is required. This consumer endpoint is accessed through a community library and has no availability guarantee; an outage displays a retry message. Server and browser caches are bounded and the API requires a Supabase session, validates input and limits request bursts. Speech synthesis needs internet access.

Speaking exercises record a complete utterance with MediaRecorder, requesting mono audio, echo cancellation and noise suppression where the browser supports them. Press the microphone again to finish; recordings stop automatically after 30 seconds. The authenticated `/api/transcription` endpoint sends audio to Groq's `whisper-large-v3` with the lesson language, using the existing `GROQ_API_KEY`. Safari MP4 and Chromium WebM are supported. Recordings remain in memory and are not saved by this platform. The reference answer is never included in the transcription prompt. The score measures word similarity in sequence, including missing, repeated and extra words; it does not assess phonetic pronunciation. Permission errors and transcription failures remain visible, and navigation cancels recording and closes microphone tracks. Microphone access requires HTTPS or localhost.

## Security

- The Groq key lives only on the server; the browser calls `/api/lesson`, which verifies the user's Supabase token before calling the AI.
- The Supabase `anon` key is public by design — data access is enforced by RLS.
